# fast-grapheme-segmenter

Fast, lightweight, **forward-only** segmentation of text into Unicode **extended grapheme clusters** ([UAX #29](https://www.unicode.org/reports/tr29/)).

This crate does one simple thing: Iterate grapheme clusters from the start of a string towards the end. There is no backward iteration, no seeking, no chunked input, and no legacy cluster mode.

- Unicode 17.0, tables regenerated by `scripts/unicode.py`
- Extended grapheme clusters only. GB9a, GB9b and GB9c always apply
- `no_std`, no `unsafe`, zero dependencies.
- Only ~19 KB of generated tables

The algorithm is a Rust port of the [unicode-segmenter], the JavaScript library it was originally developed for, replicating the [`Intl.Segmenter`] behavior.

And it's highly optmized for simple foward segmentation and counting grapheme clusters in a given text.

## Conformance

This crate agrees with `icu_segmenter` on the segmentation of every case in the official Unicode 17 `GraphemeBreakTest.txt`, of 20,000 pseudo-random rule-stress strings.

See [`tests/conformance.rs`](tests/conformance.rs).

## Usage

```rust
use fast_grapheme_segmenter::{graphemes, count_graphemes};

let text = "🏳️‍🌈🇰🇷a";

// Iterate clusters as string slices...
let clusters: Vec<&str> = graphemes(text).collect();
assert_eq!(clusters, ["🏳️‍🌈", "🇰🇷", "a"]);

// or just count them.
assert_eq!(count_graphemes(text), 3);
```

Byte offsets, e.g. for editor cursors:

```rust
use fast_grapheme_segmenter::grapheme_indices;

let offsets: Vec<usize> = grapheme_indices("a🇰🇷b").map(|(i, _)| i).collect();
assert_eq!(offsets, [0, 1, 9]);
```

Or as an extension trait:

```rust
use fast_grapheme_segmenter::GraphemeSegmentation;

assert_eq!("뎌쉐".count_graphemes(), 2);
```

Byte offsets only, without slicing the clusters out — the shape cursor
motion wants:

```rust
use fast_grapheme_segmenter::grapheme_boundaries;

let offsets: Vec<usize> = grapheme_boundaries("a🇰🇷b").collect();
assert_eq!(offsets, [0, 1, 9]);
```

`.count()` on any of the iterators delegates to the allocation-free `count_graphemes` loop, so iterator-style counting is just as fast.

## WebAssembly

The core also speaks UTF-16, as JavaScript and the wasm targets store their strings: `count_graphemes_utf16` and `grapheme_boundaries_utf16` take `&[u16]` and return code-unit offsets, so nothing is ever transcoded.

Unpaired surrogates are their own cluster, the icu4x policy for ill-formed input.

The [`wasm/`](./wasm) directory builds a ~41 KB module (after `wasm-opt`) exposing that as a raw C ABI, with a dependency-free ES-module wrapper:

```js
import { load } from './wasm/grapheme-segmenter.mjs';

const seg = await load(wasmBytes);
seg.count('🏳️‍🌈🇰🇷a');   // 3
seg.boundaries('a🇰🇷b'); // [0, 1, 5]
seg.clusters('a🇰🇷b');  // ['a', '🇰🇷', 'b']
```

A `wasm-bindgen` pkg with a typed JS/TS API builds from the same crate with `./build.sh --bindgen`.

Both builds replay the full Unicode 17 `GraphemeBreakTest.txt` through the actual module in `node test.mjs`.

## How it works

Why is this faster and lighter than other libraries?

- **Purpose-built crate:** A minimalistic interface extracted solely for forward-only grapheme segmentation. No backward iteration, no seeking, no chunked input.
- **Tiered category resolution:** Each codepoint falls through the cheapest tier covering it. A single indexed load in the direct windows, arithmetic on the value for ranges derivable from the UCD's own definitions (Hangul LV/LVT, variation selectors, the CJK gap), or a binary search over the packed residual for the rare tail.
* **Single-byte rule state:** The context the stateful rules need (GB9c, GB11, GB12/13) is packed into one `u8` that carries across cluster boundaries.
- **Compile-time packed boundaries:** All pairwise UAX \#29 rules are pre-evaluated at compile time into a 256-byte table indexed by the runtime state.
- **Sampled loop dispatch:** A 64-byte head sample picks between the per-codepoint loop and the wholesale one; both are correct for any input, so a misleading sample can only ever cost speed.
- **Word-at-a-time ASCII bulk counting:** Runs of printable ASCII, inside which every adjacent pair is unconditionally a boundary (GB999), are swallowed 8 bytes at a time with branchless SWAR masks and folded into a single pair-mask test plus arithmetic.

## Updating Unicode data

```
python3 scripts/unicode.py
```

downloads the UCD files for the version pinned in the script (cached under `scripts/ucd/`), verifies every arithmetic shortcut and the InCB derivation against the parsed data, replays the emitted lookup over all 1 114 112 codepoints, and regenerates `src/tables.rs` and `tests/testdata.rs`.

## When not to use this

- You need backward iteration, arbitrary seek positions or chunked input: use [`unicode-segmentation`](https://docs.rs/unicode-segmentation).
- You need locale-aware word/sentence/line breaking with dictionary support: use [`icu_segmenter`](https://docs.rs/icu_segmenter).
- You need legacy grapheme clusters (pre-Unicode-4.0 tailoring): nothing modern should.
