# fast-grapheme-segmenter-wasm

WebAssembly build of [`fast-grapheme-segmenter`](..), in two flavors from one cdylib:

- **Raw C ABI** (`./build.sh` -> `grapheme-segmenter.wasm`, ~41 KB after `wasm-opt`): 
  no `wasm-bindgen`, no runtime, no dependencies beyond the segmenter. 
  UTF-16 entry points hand JavaScript its own string indices with no transcoding on either side; 
  `grapheme-segmenter.mjs` is a dependency-free wrapper over it.
- **wasm-bindgen** (`./build.sh --bindgen` -> `pkg/` and `pkg-node/`):
  typed JS/TS API with generated `.d.ts`, taking `&str` and letting wasm-bindgen marshal.

```
./build.sh --bindgen && node test.mjs
```

replays every case of the official Unicode 17 `GraphemeBreakTest.txt` through both builds (the UCD file appears in `scripts/ucd/` after one run of the generator), plus handcrafted edge cases including lone surrogates.

## Raw C ABI exports


| export | signature | notes |
|---|---|---|
| `fgs_unicode_version` | `() -> u32` | `major << 16 \| minor << 8 \| patch` |
| `fgs_alloc` | `(len: usize) -> *mut u8` | 8-byte aligned; may grow memory |
| `fgs_free` | `(ptr, len)` | same `len` as the allocation |
| `fgs_count_utf8` | `(ptr, len) -> usize` | `usize::MAX` if not UTF-8 |
| `fgs_count_utf16` | `(ptr, len) -> usize` | `len` in `u16` units |
| `fgs_boundaries_utf8` | `(ptr, len, out, out_len) -> usize` | writes ≤ `out_len` `u32`s, returns the total |
| `fgs_boundaries_utf16` | same, units | offsets are UTF-16 code units |


The allocator is Rust's (dlmalloc via `std`); buffers must be released with `fgs_free` and the same length.

Growth detaches JS `ArrayBuffer` views, so re-create `TypedArray`s after every allocation.

## wasm-bindgen exports

`unicode_version()`, `count(s)`, `count_utf16(units)`, `boundaries(s)`, `boundaries_utf16(units)`.

All bindings generated by wasm-bindgen toolchain.

The `wasm-bindgen` dependency is pinned to the version of `wasm-bindgen-cli` in use; bump them together.

## JS wrapper (raw path)

`grapheme-segmenter.mjs` is a dependency-free ES module:

```js
import { load } from './grapheme-segmenter.mjs';

const seg = await load(readTheWasmFileSomehow());

seg.unicodeVersion;     // '17.0.0'
seg.count('🏳️‍🌈🇰🇷a');     // 3
seg.boundaries('a🇰🇷b'); // [0, 1, 5] — plain JS string indices
seg.clusters('a🇰🇷b');   // ['a', '🇰🇷', 'b']
```

Each call allocates, fills, and frees its buffers; for hot paths over many strings, hoisting those buffers is the obvious next step the thin wrapper deliberately leaves to you.

## Ill-formed input

Unpaired surrogates decode as `U+FFFD`. So each is its own cluster and never glues to its neighbors.
